# Contributing to WorkOrbit

Contributions are welcome.

## Development

Before opening a pull request:

1. Create an issue for substantial changes.
2. Create a focused feature or fix branch.
3. Keep changes scoped to the issue.
4. Run the relevant tests and checks.
5. Explain the change clearly in the pull request.

## Branches

Use:

- `feat/*` for features
- `fix/*` for bug fixes
- `refactor/*` for refactoring
- `docs/*` for documentation

## Pull Requests

A good PR should include:

- What changed
- Why it changed
- How it was tested
- Screenshots for significant UI changes

## Scope

WorkOrbit is still under active development. If a proposed change affects escrow logic, payments, authentication, or wallet security, discuss it before implementation.

## Code of Conduct

Be respectful, constructive, and collaborative. Harassment and gatekeeping are not acceptable.

## Upstream

WorkOrbit is derived from the open-source Stellance project. Contributors should preserve applicable copyright and license notices when modifying upstream code.
